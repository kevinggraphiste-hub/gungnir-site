Installation · Guide complet

Deux voies pour démarrer Gungnir.

Cloud Scarlet Wolf en 30 secondes, ou self-hosted Docker en une commande.
Choisissez celle qui correspond à votre niveau de souveraineté.

Avant de choisir

Cloud ou self-hosted ?

Voie 1 · Cloud Scarlet Wolf

Pour qui ?

  • Vous voulez tester sans rien installer
  • Vous n'avez pas de VPS ni de DSI
  • Vous acceptez que vos données vivent sur le VPS Scarlet Wolf (Suisse)
  • Vous voulez une mise à jour automatique

14 jours d'essai offerts (4 modèles LLM gratuits inclus), puis configuration de vos propres clés API providers.

Voie 2 · Self-hosted

Pour qui ?

  • Données confidentielles ou réglementées (juridique, santé, défense)
  • Vous avez un VPS ou un serveur Docker
  • Vous voulez auditer le code et contrôler les mises à jour
  • Mode 100 % local possible (Ollama + Qdrant en interne)

Code source-available sous BSL 1.1, image Docker pré-buildée disponible sur GHCR.

Voie 1 · Cloud Scarlet Wolf

Essai 14 jours, sans carte bancaire.

  1. Allez sur gungnir.scarletwolf.cloud
  2. Créez votre compte (email + mot de passe, ou OAuth Google / GitHub)
  3. Onboarding conversationnel : l'agent vous demande votre nom, vos préférences, votre métier
  4. 4 modèles LLM gratuits débloqués pendant l'essai (Llama, Mistral, Gemini Flash, Claude Haiku, sur OpenRouter)
  5. Au bout de 14 jours, configurez vos propres clés API providers et continuez à votre rythme

Aucun engagement, suppression du compte instantanée si vous changez d'avis. Vos données partent avec un certificat cryptographique d'effacement.

Démarrer l'essai maintenant

Voie 2 · Self-hosted Docker

Sur votre VPS, en une commande.

Pré-requis : un serveur Linux avec Docker + Docker Compose installés. RAM mini 4 Go, recommandé 8 Go. Stockage 20 Go libres.

Méthode A · Image Docker

Recommandée (clé en main, ~2 min)

Une commande qui télécharge tout, configure les secrets, démarre les services.

curl -fsSL https://raw.githubusercontent.com/kevinggraphiste-hub/Gungnir/main/install.sh | bash

Ça crée un dossier gungnir/, génère les secrets, pull l'image depuis GHCR, démarre Postgres + l'app + le sidecar updater. Vous accédez ensuite à http://votre-vps:8000 et créez votre compte admin.

Méthode B · Build source

Pour développeurs / audit (~5 min)

Vous clonez le repo, vous buildez l'image localement. Idéal si vous voulez modifier le code ou ajouter vos propres plugins.

git clone https://github.com/kevinggraphiste-hub/Gungnir.git
cd Gungnir
# génère .env avec 3 secrets requis
docker compose up -d --build

Voir INSTALL.md pour la configuration .env détaillée (DATABASE_URL, GUNGNIR_SECRET_KEY, GUNGNIR_UPDATER_SECRET).

Après l'installation

Premiers pas, dans l'ordre.

Étape 1

Configurer un LLM

Settings → Fournisseurs IA. Au minimum une clé API OpenRouter (8 providers d'un coup) ou Anthropic / OpenAI / Mistral. Pour le mode local : ajoutez Ollama.

Étape 2

Onboarding agent

L'agent vous demande nom, formality, soul. C'est la base de son identité. Vous pouvez la modifier après dans Settings → Général.

Étape 3

Marketplace

Réglages → Marketplace. Parcourez les modules de la communauté, installez ceux qui vous parlent (voix premium, automatisations métier, etc.). Vous pouvez aussi publier les vôtres.

Maintenance

Mises à jour : automatiques ou manuelles.

Settings → Mises à jour : bouton « Vérification automatique » qui fetch GitHub toutes les 6 h. Quand une nouvelle version sort, un point vert apparaît dans la sidebar. Vous cliquez « Mettre à jour » : le sidecar gungnir-updater fait checkout du nouveau tag, build, healthcheck, rollback automatique si échec. ~30 secondes en mode image, ~5 min en mode build.

Backups : Settings → Backup. Export complet (utilisateurs, conversations, conscience, plugins, configs) en un clic, format ZIP. Restoration en uploadant le ZIP. Compatible entre instances (vous pouvez migrer d'un VPS à un autre).

Besoin d'aide

On peut le faire ensemble.

Pas de DSI, pas de temps, pas envie de toucher à Docker ? Réservez 30 minutes, on installe Gungnir avec vous sur votre VPS.
