Vue d'ensemble

Une plateforme full-stack, pas un wrapper.

Gungnir est un super-assistant full-stack : backend FastAPI (Python), frontend React + Vite + TypeScript, base PostgreSQL 16, le tout conteneurisé Docker. Architecture à plugins (manifest + routes), agent outillé (système de tools « WOLF »), conscience vectorielle persistante, et 14 providers LLM supportés (OpenRouter par défaut, Anthropic, OpenAI, Google, MiniMax, Ollama, etc.).

L'apprentissage continu existe partout. Le pilotage humain de cet apprentissage, non. C'est la signature Scarlet Wolf.

Architecture cognitive

Soul · Skill · Personnalité : trois couches indépendantes.

Là où la plupart des IA empilent des prompts dans une seule ficelle, Gungnir sépare trois couches réglables séparément : identité stable et compétences ciselées.

ᛞ
Couche 1 · Soul

Qui il est

Formality (tu/vous), formation, convictions, ton. Posée à l'onboarding, persistée par utilisateur, évolue par revue humaine. Stockée hors-prompt, injectée au runtime.

ᚱ
Couche 2 · Skills

Ce qu'il sait faire

Chaque compétence est un module isolé et composable (rédaction, recherche jurisprudentielle, analyse PDF, génération de code). Améliorées par revue, sans polluer l'identité.

ᛉ
Couche 3 · Personnalité

Comment il agit

Mode opératoire du moment : concis pour un brief, exploratoire pour du brainstorming. Bascule en un clic, sans réécrire l'identité ni les skills.

Résultat : un agent qui ne perd pas son identité quand il change de tâche, et ne change pas de compétence quand il change d'humeur.

Conscience vectorielle

La mémoire qui humanise l'apprentissage continu.

Une conscience par utilisateur, isolée, exportable. Elle structure ce que l'agent retient et déclenche des comportements proactifs au bon moment. Là où une IA classique oublie tout, Gungnir apprend et se souvient : 7 boucles automatiques, 5 besoins fondamentaux, 13 triggers câblés, et un kill-switch à 3 paliers qui garde l'humain aux commandes.

Backends vectoriels supportés

Qdrant · Pinecone · Chroma · Supabase

Choix du store selon votre contrainte : Qdrant dédié (recommandé souveraineté), Chroma embarqué (100 % local), Pinecone/Supabase (managé). Logs d'audit possibles sur une instance séparée du contenu fonctionnel.

Souveraineté technique

100 % local possible, sans compromis.

Sur données juridiques/médicales/défense, le cloud est interdit. Gungnir tourne entièrement sur votre machine ou votre VPS, sans appel externe.

  • LLM local via Ollama : Llama, Mistral, Qwen, Phi, etc. (8B à 70B sur infra modeste)
  • Mémoire vectorielle locale : Qdrant ou ChromaDB embarqués
  • Voix locale : Whisper.cpp (transcription), piper-tts (synthèse)
  • Recherche locale : index full-text, pas d'API web
  • Aucune télémétrie sortante : vérifiable au pare-feu
Briques de la stack

Composants

  • Ollama : modèles locaux, option 100 % on-prem
  • Qdrant : mémoire vectorielle dédiée
  • OpenRouter : agrégation multi-providers LLM (cloud)
  • Forge : orchestration workflows YAML (type n8n)
  • 9 providers de recherche : DuckDuckGo, Tavily, Brave, Exa, etc.
  • 4 providers vocal : ElevenLabs, OpenAI Realtime, Gemini Live, Grok
Déploiement self-host

Une commande, Docker, à vous.

Installation clé en main via Docker :

curl -fsSL https://<votre-source>/install.sh | bash

  • OAuth Google / GitHub configurable
  • Marketplace publique pour ajouter des plugins community (signés Ed25519)
  • Mises à jour par tag SemVer : déploiement automatisé (build + healthcheck + rollback)
  • Sauvegardes intégrées, restauration documentée

Sécurité & isolation

Cloisonnement par conception.

Par utilisateur

État, config, triggers, mémoire : tout est instancié par utilisateur. Une clé API d'un user ne peut jamais servir un autre.

Journaux d'audit

Logs immuables et signés, possibilité d'une instance vectorielle d'audit séparée du contenu, export au format de votre superviseur.

Effacement certifié

Suppression complète <24 h avec certificat cryptographique signé. Audit-ready RGPD.

Licences

Source-available, sans schizophrénie.

Trois licences, trois philosophies cohérentes :

  • SpearCode (Apache 2.0) : génération de code, vraiment libre et réutilisable.
  • Munnin (MIT) : couche d'agrégation LLM, prenez-la, faites-en ce que vous voulez.
  • Gungnir complet (BSL) : l'expérience complète, auditable, qui bascule en Apache 2.0 après 4 ans.

Un écosystème ouvert vaut mieux qu'un produit fermé. Ce qui nous distingue, ce n'est pas la fermeture, c'est l'orchestration.
